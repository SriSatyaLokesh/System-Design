**TOOL-01: Cursor - Repository-Aware AI Editor**
- What: AI-first code editor with native repository understanding, built on VS Code
- Philosophy: Seamless AI integration, codebase-aware suggestions, natural conversation with your code
- Prerequisites: 
  - MacOS, Windows, or Linux
  - No separate API key needed (Cursor provides built-in AI)
  - Optional: OpenAI API key for GPT-4 access
- Installation:
  1. Download from cursor.sh
  2. Install and launch (imports VS Code settings automatically)
  3. Verify: Open project, press Cmd+K (Mac) or Ctrl+K (Windows), type a command
- Workflow example: "Refactor user authentication to use OAuth instead of JWT"
  - Open project in Cursor
  - Press Cmd+K to open AI chat
  - Type your request with context (Cursor already knows your codebase)
  - Review proposed changes across multiple files
  - Accept/modify inline
- Key features:
  - **Cmd+K command mode**: Give instructions, get multi-file changes
  - **Codebase indexing**: AI understands entire project structure
  - **Inline editing**: Changes applied directly with diff view
  - **Composer mode**: Multi-step changes across many files
  - **Privacy modes**: Use local models or cloud models
- Tips:
  - Start with small requests to understand capabilities
  - Use Cmd+K for big changes, Tab for autocomplete
  - Review all changes before accepting
  - Check privacy settings if working with sensitive code
- Link to hands-on exercise (Exercise 3)
- Official docs: https://cursor.sh/docs

**Structure:**

## Prompt Engineering Fundamentals

### What Is Prompt Engineering?
[1-paragraph explanation: The practice of crafting effective instructions for AI tools to get desired outcomes]

### Why It Matters
- Better prompts = better results
- Saves time (fewer iterations)
- Works across all AI tools (assistants, agents, copilots)
- Transferable skill

### Progressive Skill Levels

#### Level 1: Basic Requests
**Good prompt anatomy:**
- Context: What you're working on
- Task: What you want the AI to do
- Constraints: Format, style, limitations (if applicable)

**Example - Basic:**
 Bad: "Help me with my code"
- Too vague, no context, unclear outcome

 Good: "Review this Python function that sorts user data by date. Check for edge cases and suggest improvements."
- Clear task, provides context, specific request

**Why it's better:** Specific task, mentions language, indicates what to check for

---

#### Level 2: Adding Context
**Pattern:** Show relevant code, explain goals, specify constraints

**Example - With Context:**
 Bad: "Write a function to validate emails"
- No language specified, no requirements

 Good: "Write a TypeScript function that validates email addresses. It should:
- Return boolean (true if valid)
- Handle common edge cases (missing @, multiple @)
- Include JSDoc comment
- Follow this project's existing validation pattern: [paste example]"
- Language specified, return type clear, edge cases noted, style reference included

**Why it's better:** Specific language, clear requirements, style consistency, edge cases considered

---

#### Level 3: Iterative Refinement
**Pattern:** Start broad, refine based on response

**Example - Iteration:**
First prompt: "Explain React hooks to someone learning React"
AI responds: [General explanation]

Second prompt: "Focus on useState and useEffect. Give me practical examples of when to use each in a real component."
AI responds: [More specific examples]

Third prompt: "Show me how useEffect cleanup functions prevent memory leaks, with a concrete example."
AI responds: [Detailed, specific answer]

**Why iteration works:** Narrows focus, builds on prior context, gets increasingly specific

---

#### Level 4: Strategic Prompting
**Pattern:** Break complex tasks into steps, provide comprehensive context

**Example - Complex Task:**
"I'm building a user authentication system in Next.js 15 with the App Router. I need to:
1. Create a login form component with email/password fields
2. Use Server Actions for form submission
3. Validate credentials against a PostgreSQL database using Prisma
4. Set a JWT in httpOnly cookie with 15-minute expiry
5. Handle errors gracefully with toast notifications

Start with step 1: the login form component. Use Tailwind for styling, include accessibility attributes, and show validation feedback."

**Why this works:** Clear context (tech stack), broken into steps, specific starting point, detailed requirements per step

---

### Common Anti-Patterns

####  Anti-Pattern 1: No Context
"Fix this bug" [without showing code or explaining what's wrong]
 **Fix:** Show the code, describe expected vs actual behavior

####  Anti-Pattern 2: Unclear Outcome
"Make this better"
 **Fix:** Specify what "better" means (faster, more readable, fewer dependencies)

####  Anti-Pattern 3: Over-Constraining
"Write this function using exactly 5 lines, no loops, no libraries, must run in 1ms"
 **Fix:** Provide reasonable constraints, allow AI to suggest best approaches

####  Anti-Pattern 4: Not Iterating
Accepting first response without refinement
 **Fix:** Ask follow-ups, request alternatives, clarify ambiguities

####  Anti-Pattern 5: Copy-Paste Without Understanding
Blindly accepting code without reading/understanding
 **Fix:** Ask for explanations, request comments, understand before using

---

### Quick Tips
1. **Be specific:** Language, framework versions, requirements
2. **Show examples:** Existing patterns to follow
3. **State constraints:** Format, style, limitations
4. **Iterate:** First response is starting point, not final answer
5. **Ask for explanations:** "Explain why you chose this approach"
6. **Request alternatives:** "Show me another way to solve this"
7. **Verify understanding:** "Show me the edge cases this handles"

## Hands-On Exercises

### About These Exercises
These exercises help you practice with each tool and apply prompt engineering principles. Each exercise takes 10-20 minutes and has clear success criteria so you know when you're done.

### Exercise 1: GitHub Copilot - Generate a Validated Function

**Scenario:** You need to create a user registration function that validates input data.

**Goal:** Use GitHub Copilot to generate a TypeScript function with validation logic and type safety.

**Prerequisites:**
- GitHub Copilot installed and active
- VS Code (or supported IDE) open
- TypeScript project (or create simple .ts file)

**Steps:**

1. **Create a new file:** `user-registration.ts`

2. **Write a descriptive comment:**
   ```typescript
   // Function that validates and registers a new user
   // - Email must be valid format
   // - Password must be at least 8 characters
   // - Username must be 3-20 characters
   // - Returns success message or error details
   ```

3. **Start function signature:**
   ```typescript
   function registerUser(email: string, password: string, username: string):
   ```

4. **Accept Copilot suggestions** and iterate:
   - Review the generated function
   - If validation is incomplete, add comments for missing checks
   - Accept or modify suggestions

5. **Test the function** with sample inputs

**Success Criteria:**
 Function has TypeScript types
 All three validation rules implemented
 Returns clear success/error messages
 Code is readable and commented

**Reflection Questions:**
- How did the comment quality affect suggestions?
- Did you need to iterate? What did you refine?
- How would you improve the prompt for better initial results?

---

### Exercise 2: Claude Code (or Chat AI) - Refactor for Readability

**Scenario:** You have a complex function that works but is hard to read. Use AI to refactor it.

**Goal:** Practice iterative prompting to improve code quality.

**Sample Code to Refactor:**
```javascript
function p(d){let r=[];for(let i=0;i<d.length;i++){if(d[i].a&&d[i].s>100){r.push({n:d[i].n,v:d[i].p*d[i].q})}}return r.sort((a,b)=>b.v-a.v)}
```

**Steps:**

1. **Initial prompt (Level 1 - Basic):**
   "Refactor this function for readability"
   [Paste code]

2. **Refined prompt (Level 2 - With Context):**
   "Refactor this JavaScript function for readability:
   - Use descriptive variable names
   - Add comments explaining logic
   - Separate concerns (filter, map, sort)
   - Use modern ES6+ features"
   [Paste code]

3. **Iteration (Level 3):**
   After receiving refactored code, ask:
   "Can you explain what this function does and suggest performance improvements?"

4. **Final iteration (Level 4):**
   "Add TypeScript types to this function and unit test examples"

**Success Criteria:**
 Function is readable with clear variable names
 Logic is separated and commented
 You understand what the function does
 (Optional) TypeScript types and tests added

**Reflection Questions:**
- How did prompt specificity change the outcome?
- What did you learn from the iteration process?
- Which prompt level gave you the most value?

---

### Exercise 3: Multi-Tool Workflow - Build a Feature

**Scenario:** Build a complete feature using multiple AI tools strategically.

**Goal:** Understand when to use Chat AI vs Copilot/Code AI.

**Task:** Create a "Task List" component with add/delete functionality

**Workflow:**

1. **Planning (Chat AI - ChatGPT/Claude):**
   Prompt: "I'm building a task list component in React. What state management approach would you recommend for add/delete functionality? Keep it simple for a learning project."
   - Get conceptual guidance
   - Understand patterns

2. **Implementation (GitHub Copilot or Claude Code):**
   - Create `TaskList.tsx` file
   - Use Copilot to generate component structure
   - Write comments describing needed functions
   - Accept/iterate on suggestions

3. **Debugging (Context-dependent):**
   - If single-function issue: Either tool works
   - If multi-component issue: Prefer Repo AI (Claude Code)

4. **Learning (Chat AI):**
   Prompt: "Explain why we use useState for local component state vs useContext for global state"

**Success Criteria:**
 Task list component works (can add/delete tasks)
 You used Chat AI for concepts, Repo AI for implementation
 You can explain when you switched tools and why
 Component is functional and readable

**Reflection Questions:**
- When did you switch between tools? What triggered the switch?
- Which tool felt more natural for which type of work?
- How would you apply this workflow to your next project?

---

### Exercise 4: Prompt Engineering Practice

**Goal:** Apply prompt engineering levels to real tasks.

**Task:** For each scenario, write prompts at different levels and compare results.

**Scenarios:**

1. **Scenario A:** "Explain how promises work in JavaScript"
   - Write a Level 1 prompt (basic request)
   - Write a Level 2 prompt (with context: "I understand callbacks but struggle with promise chaining")
   - Try both, note differences

2. **Scenario B:** "Create a form validation function"
   - Write a vague prompt (anti-pattern)
   - Write a specific prompt (Level 4 strategic)
   - Compare outputs

3. **Scenario C:** Pick your own coding challenge
   - Start vague, then iterate 3 times
   - Document your iteration process
   - Reflect on how outcomes improved

**Success Criteria:**
 Completed at least 2 scenarios
 Documented prompts and responses
 Identified which prompt techniques worked best
 Can articulate why specific prompts produced better results

**Reflection:**
- Which skill level felt most useful?
- What prompt patterns will you use regularly?
- What anti-patterns did you catch yourself doing?
