**5. Delegation Patterns (180-220 lines)** [AGENT-02]
- Pattern 1: Task Decomposition
  - Example: "Build auth system" → [register, login, refresh, logout]
  - Prompt template with code example
  - When to use: Large complex tasks

- Pattern 2: Specialist Delegation
  - Example: Frontend agent, backend agent, test agent
  - Handoff protocol (context + constraints)
  - Code example: Orchestrator dispatching to specialists
  
- Pattern 3: Hierarchical Delegation
  - Parent agent → child agents → execution
  - GSD example: Orchestrator → Planner/Executor/Verifier
  - Workflow diagram

- Pattern 4: Parallel Delegation
  - Independent tasks run simultaneously
  - Synchronization points (checkpoints)
  - Wave-based execution (reference GSD waves)

Code examples in Python/TypeScript:
```python
class OrchestratorAgent:
    def delegate(self, task):
        # Decompose task
        subtasks = self.planner.break_down(task)
        
        # Delegate to specialists
        results = []
        for subtask in subtasks:
            agent = self.get_specialist(subtask.type)
            result = agent.execute(subtask)
            results.append(result)
        
        # Aggregate results
        return self.synthesize(results)
```

Prompt example:
```
You are a Planning Agent. Your job:
1. Receive high-level goal from user
2. Break into 5-10 executable tasks
3. Assign wave numbers (1=no deps, 2=depends on wave 1, etc.)
4. Output structured plan in XML format

Goal: {user_goal}

Output:
<plan>
  <task wave="1">...</task>
  <task wave="1">...</task>
  <task wave="2">...</task>
</plan>
```

**6. Multi-Agent Orchestration (200-220 lines)** [AGENT-03]
- Orchestration definition: Coordinating multiple agents toward shared goal
- Communication patterns: Message passing, shared state, event-driven
- Workflow diagram - GSD example:
```
User Goal
   ↓
Orchestrator (@gsd)
   ├─→ Planner Agent
   │     └─→ Creates PLAN.md (tasks with waves)
   │            ↓
   ├─→ Executor Agents (parallel per wave)
   │     └─→ Execute tasks → code + commits
   │            ↓
   └─→ Verifier Agent
         └─→ Check goal achievement → VERIFICATION.md
```

- Synchronization strategies:
  - Checkpoints (human review points)
  - Wave boundaries (all wave N before wave N+1)
  - Event triggers (on completion, on error)

- Conflict resolution: Multiple agents modifying same resource
- Context management: Fresh contexts per agent (avoid context rot)
- Real-world example: GSD CLI orchestration walkthrough

**8. Agent Design Best Practices (100-120 lines)**
- Principle 1: Single Responsibility (one agent, one job)
- Principle 2: Clear Interfaces (input/output contracts)
- Principle 3: Graceful Degradation (handle failures)
- Principle 4: Human-in-the-Loop (checkpoints for critical decisions)
- Principle 5: Observable Behavior (logging, state tracking)
- Anti-patterns: God Agent (does everything), Mystery Agent (black box)
