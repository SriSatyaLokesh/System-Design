**4. Skill Packaging & Integration (150-180 lines)** [SKILL-02]
- Packaging pattern: Markdown file structure

**Standard Format:**
```markdown
# Skill Name

## Description
[What this skill does]

## When to Use
[Scenarios where skill applies]

## Instructions
[Step-by-step capability execution]

## Examples
[2-3 demonstration cases]

## Anti-patterns
[What NOT to do]

## Success Criteria
[How to verify successful execution]
```

- Integration patterns:

**Pattern 1: Direct Injection**
- Paste skill into system prompt
- Use case: One-time capability
- Example: Add code review skill to Claude conversation

**Pattern 2: Reference by Path**
- Store skills in repo (.github/skills/)
- Agent reads skill file when needed
- Use case: Persistent, version-controlled skills
- Example: GSD skills in this repo

**Pattern 3: Skill Registry**
- Central library of skills (npm for skills)
- Agent queries registry for capability
- Use case: Organization-wide skill sharing
- Example: Company prompt library

**Pattern 4: Skill Composition**
- Combine multiple skills for complex workflows
- Example: Code Review + Test Generation + Documentation
- Orchestration: Parent skill delegates to child skills

**5. Platform Skill Formats (150-180 lines)** [SKILL-05]
- Overview: Each platform has skill/capability conventions

**Claude Skills (Anthropic):**
- Format: Markdown with structured sections
- Size: 10-30KB (comprehensive instructions)
- Usage: Add to Project knowledge or system prompt
- Example structure:
```markdown
# Skill: [Name]

## Core Capability
[What it does]

## Detailed Instructions
[Step-by-step with examples]

## Edge Cases
[How to handle unusual inputs]
```
- Best for: Domain expertise, complex reasoning tasks

**GitHub Copilot Skills:**
- Format: SKILL.md in .github/skills/ directory
- Metadata: YAML frontmatter (name, description, when_to_use)
- Usage: Agent reads skill when invoked via @-mention or slash command
- Example: This repo''s .github/skills/execute-plan/SKILL.md
- Best for: Dev workflow automation

**OpenAI GPTs (Custom Instructions):**
- Format: Plain text system prompt (up to ~8K chars)
- Usage: GPT configuration panel
- Limitations: No file structure, size constrained
- Best for: Simple, focused capabilities

**LangChain Tools:**
- Format: Python class with description and execute method
- Integration: Registered with agent executor
- Example:
```python

    # Implementation
    return results

    name="Search Codebase",
```

**7. Skill Design Best Practices (100-120 lines)**
- Principle 1: Single Capability (one skill, one job)
- Principle 2: Clear Instructions (step-by-step, no ambiguity)
- Principle 3: Examples-Driven (show, don''t just tell)
- Principle 4: Versioned (track changes, maintain compatibility)
- Principle 5: Testable (can verify skill execution quality)

Anti-patterns:
- ❌ Vague Skill: "Be helpful" (no actionable instructions)
- ❌ God Skill: Tries to do everything (maintenance nightmare)
- ❌ Example-Free: Abstract instructions without demonstrations
- ❌ Stale Skill: Outdated, no versioning, breaks silently

Skill design workflow:
1. Identify capability gap (what''s missing?)
2. Define objective (what outcome?)
3. Write instructions (how to achieve outcome?)
4. Add 2-3 examples (demonstrate execution)
5. Test with real inputs (refine based on quality)
6. Version and document (track changes)
